# Quinn Luxurious — Stripe Test-Mode Setup Guide

This guide details the procedure for configuring Stripe test-mode payments and testing webhooks locally.

> **CRITICAL SAFETY RULE:**
> Only use Stripe **Test Mode** (`sk_test_...`, `pk_test_...`, `whsec_...`). The application contains server-side guards that automatically reject any live keys (`sk_live_...`). Never commit keys or paste secret values into chat.

---

## 1. Required Environment Variables

Add the following variables to your local `.env.local` file (and Vercel Environment Variables):

```bash
# Stripe Test-Mode Keys (Obtain from https://dashboard.stripe.com/test/apikeys)
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
STRIPE_SECRET_KEY=sk_test_...

# Stripe Local Webhook Signing Secret (Generated by Stripe CLI)
STRIPE_WEBHOOK_SECRET=whsec_...

# Public Application Base URL
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

---

## 2. Obtaining Your Test API Keys

1. Sign in to your [Stripe Dashboard](https://dashboard.stripe.com/).
2. Toggle the switch in the upper-right corner to **Test mode** (ensure the orange "TEST" badge is visible).
3. Navigate to **Developers** &rarr; **API keys**.
4. Copy the **Publishable key** (`pk_test_...`) into `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`.
5. Under **Secret key**, click **Reveal test key** and copy (`sk_test_...`) into `STRIPE_SECRET_KEY`.

---

## 3. Local Webhook Testing Procedure (Stripe CLI)

To test Stripe Checkout events and verified payment confirmation on your local development machine:

### Step 1: Install the Stripe CLI
- **Windows (via Scoop):** `scoop bucket add stripe https://github.com/stripe/scoop-stripe-cli.git && scoop install stripe`
- **Windows (via Chocolatey):** `choco install stripe-cli`
- **Direct Download:** Download the Windows executable from [GitHub Releases](https://github.com/stripe/stripe-cli/releases).

### Step 2: Authenticate the CLI
```bash
stripe login
```
Follow the browser prompt to authorize the CLI with your test account.

### Step 3: Forward Webhook Events
Run the following command while your Next.js development server is running (`npm run dev` on port 3000):

```bash
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

The terminal will print your local webhook signing secret:
```text
> Ready! Your webhook signing secret is whsec_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### Step 4: Configure the Signing Secret
Copy the `whsec_...` string into `STRIPE_WEBHOOK_SECRET` in your `.env.local` file, then restart your dev server.

### Step 5: Trigger a Test Event (Optional Validation)
In a separate terminal window, test event delivery:
```bash
stripe trigger checkout.session.completed
```
The CLI output will confirm an HTTP 200 response from `/api/webhooks/stripe`.

## 5. Security & Idempotency Guarantees

1. **Authoritative Pricing:** Service prices are retrieved directly from the database by service ID. Any client-submitted or altered price is ignored.
2. **Double-Booking Release:** If a customer initiates a Stripe Checkout session but abandons it, the slot is automatically released when the session expires or after 15 minutes.
3. **Signature Verification:** Every webhook request is strictly validated with `stripe.webhooks.constructEvent`. Unsigned or tampered payloads return HTTP 400.
4. **Idempotent Updates:** Webhook events check current appointment state before applying changes. Repeated delivery of `checkout.session.completed` does not cause duplicate updates or repeated side effects.
5. **No Client Trust:** Redirecting to `/appointment/success` alone does not mark an appointment as paid. The appointment is only confirmed upon cryptographic webhook verification or verified server-to-server retrieval.
